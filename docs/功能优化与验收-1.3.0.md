# 1.3.0：新生情景演练与校园探索行程

2026-10-13至10-14，在已交付的1.2.0（8ea7c08）上继续优化。原作者的校园资料、地图、宿舍与成长模块保留；本轮新增情景练习内容、行程编排、会话保存和交互验证。原作者仍为参赛人，本轮是委托协助开发，不改写原始贡献归属。

## 这次解决什么问题

现有资料浏览和个人待办需要用户主动判断“这条资料是不是当前安排”“看完应该做什么”。这轮用报到场景把这种判断变成可操作练习，并把单地点地图变成能够持续保存的探索计划。

| 功能 | 可以实际操作 | 适用边界 |
| --- | --- | --- |
| 新生情景演练 | 三阶段9场景、每题3处理方式、解释与建议、原文依据、复习待改进场景 | 是资料理解练习，推荐选项可见，不是考试、官方评分或注册证明 |
| 准备衔接 | 查看现有准备完成数，跳到清单亲自核对；可继续问相关问题 | 答对不会自动完成准备，最近一次选择决定复习状态 |
| 校园探索 | 3条参考行程，从45地点选最多8个；排序、移除、到访、只看行程 | 未确认开放时段；不提供道路、距离、步行时长、GPS或最短路 |
| 带走计划 | 导出按当前顺序排列的TXT，含到访状态与地点说明 | 全部记录JSON也含演练与行程；新增两类数据没有导入恢复功能 |
| 持续保存 | SQLite按会话保存，刷新继续，多页更新检测revision冲突 | 单机本地服务；未实现帐号或跨设备同步 |

场景覆盖：往年报到截图、随身证件、陌生收款码、晚到接站、同名建筑、收藏床位、图书馆开放与路线、社团实际开设、竞赛认定。全部引用现有资料，并保留历史参考和第三方限制。本轮没有确认新学年报到安排或本校实际招新。

## 两分钟演示

1. 启动后首页进入演练。先选“按截图日期买票”，确认后看到建议与待复习状态；再选“先核对当年入学须知和学校通知”，保存后状态变为已了解。
2. 展开“查看本场景依据与适用范围”，再展开具体资料，看原文和适用提醒。清单仍保持用户原来的进度。
3. 打开地图，点击“看看学习空间”，生成厚德楼、实训中心（中）、图书馆3地点。
4. 勾选图书馆已到访，点击“上移图书馆”；顺序变为厚德楼→图书馆→实训中心（中）。地图编号与连线随之改变。
5. 切换“仅显示行程地点”并刷新，排序与到访勾选保留。导出TXT，核对顺序与“不是实际道路”的提示。

参考行程更换和清空会请求页面确认。更换行程保留共同地点的到访状态，其他地点移出当前行程；清空仅清除当前行程与到访勾选，不影响演练、问答、清单或任务。

## 复现与升级

从运行包解压启动即可。替换程序前停止旧进程；如需保留记录，保持原`.runtime`目录和浏览器当前会话标识。启动自动创建新增的两个表，不清理现有数据。备份数据库时应先停止服务，再复制`.runtime`目录。

新增接口和数据结构见[架构与接口](架构与接口.md)。程序默认不读取旧密钥、不访问模型或搜索引擎；演练和行程为本地规则与SQLite操作。本轮未测试真实付费模型、未公开发布、未代办赛事提交。
