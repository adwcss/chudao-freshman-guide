# 河科职大新生指南智能问答助手 —— 项目交接与国赛冲刺指南

## 一、项目是什么（一句话）

一个基于 **RAG（检索增强生成）** 的校园新生问答助手：把 13 份河南科技职业大学迎新资料切块后存入 Chroma 向量库，用户提问时先向量检索相关资料，再让 DeepSeek 大模型严格依据资料作答，并附可展开的引用来源；另附校园地图页（报到路线 + 地点速查 + 地图缩放）。

- 前端：Streamlit（聊天 + 地图双 Tab 页面）
- 后端：FastAPI（聊天 / 地点 / 统计三个接口）
- 向量库：ChromaDB + 多语言 embedding（paraphrase-multilingual-MiniLM-L12-v2）
- 大模型：DeepSeek（deepseek-chat，OpenAI 兼容接口，流式输出）
- 最终访问地址（本地运行）：**http://localhost:8501/**
- 项目原始压缩包：`D:\新生指南.zip`（约 473 MB，内含 .venv 虚拟环境）

## 三、操作手册（接手第一步：把项目跑起来）

### 0. 解压与放置
1. 把 `D:\新生指南.zip` 解压到 **D 盘根目录**，得到 `D:\新生指南\`（代码里有多处硬编码绝对路径，如地图图片 `d:\新生指南\校园地图.png`，**不要随便换盘/换路径**，否则会找不到图）。
2. 项目自带 `.venv` 虚拟环境（Python 3.12），大部分依赖已装好。

### 1. 确认 API 密钥
- 打开 `D:\新生指南\backend\.env`，确认 `DEEPSEEK_API_KEY` 是真实可用的 sk- 密钥（当前已填了一个，若调用报 401 说明失效，需到 DeepSeek 开放平台申请新 key 填入）。
- `.env` 含密钥，**严禁提交到 Git 仓库**（已在 .gitignore 中排除则没问题，需确认）。

### 2. 重建知识库向量库（新增/修改资料后必须执行）
```powershell
cd D:\新生指南\backend
..\.venv\Scripts\python.exe scripts\ingest.py
```
- 脚本会自动：切分 13 份资料 → 清空旧集合 → 重新向量化入库 → 写更新时间。
- 首次运行会从 HuggingFace 镜像下载 embedding 模型（国内已配 hf-mirror），需联网等待几分钟。

### 3. 启动后端（FastAPI，端口 8000）
```powershell
cd D:\新生指南\backend
..\.venv\Scripts\python.exe -m uvicorn main:app --reload --port 8000
```
- 验证：浏览器打开 `http://localhost:8000/` 应返回健康检查 JSON。

### 4. 启动前端（Streamlit，端口 8501）
```powershell
cd D:\新生指南\frontend
..\.venv\Scripts\python.exe -m streamlit run app.py
```
- 浏览器访问 **http://localhost:8501/**（这就是作品的最终展示地址，评委看的就是它）。

### 5. 验收清单（跑通后逐项点一遍）
- [ ] 首页统计条显示知识库 chunk 数
- [ ] 点 FAQ 按钮「学费怎么交？」能流式回答并带来源
- [ ] 问一个知识库外问题（如「学校有游泳池吗」）应触发兜底话术，不编造
- [ ] 地图页：报到路线卡、地图缩放、地点胶囊按钮「馨园宿舍在哪」能回答
- [ ] 断网/停掉后端时，前端给出友好报错而不是白屏

## 五、需要优化的内容（按评分维度，冲刺高分的关键）

评分权重：过程可复现 25% / 实用价值 25% / 方法创新 20% / 工程质量 15% / 用户体验 15%。

### A. 工程质量与架构（15%）
1. **硬编码路径清理（必做）**：前端 `app.py` 里 `MAP_IMAGE_PATH = r"d:\新生指南\校园地图.png"`、后端 `ingest.py` 的 `DOCS_DIR` 都是绝对路径，换机器必炸。改为相对路径（基于 `__file__` 推导）或读取环境变量。
2. **CORS 收紧**：后端 `main.py` 目前 `allow_origins=["*"]`，上线/演示前收紧为前端实际来源（`http://localhost:8501`）。
3. **密钥安全**：确认 `.env` 在 `.gitignore` 中；README 里提供 `.env.example` 模板（不写真实 key）。
4. **依赖锁定**：requirements.txt 目前是最低版本（如 `fastapi>=0.110.0`），建议 `pip freeze > requirements.txt` 锁定精确版本，保证评委 10 分钟复现不翻车。
5. **版本号与服务名**：main.py 版本升到 v1.0.0，接口加 `/health` 心跳、统一异常处理、访问日志。
6. **Docker 化（强烈建议）**：写 Dockerfile + docker-compose（backend + frontend + 挂载知识库），评委一键 `docker compose up` 即可复现，这是「10 分钟极速复现」的最优解。
7. **单元测试**：至少给 `splitter`、`retriever`、`is_relevant` 写几个 pytest 用例，体现工程质量。

### B. 解题有效性与实用价值（25%）
1. **知识库扩内容**：现有 13 份资料约 40KB，偏少。建议补：奖学金与助学金细则、选课与学分制度、校园网/一卡通办理、银行卡/医保办理、社团与学生会、专升本与考研政策、校历与假期安排、毕业与就业信息。资料仍以官方来源优先。
2. **做「多轮对话」**：现在每次提问都是独立问题，用户追问「那学费呢？」AI 不知道上文。接入会话历史（把最近 N 轮问答拼进 prompt），体验提升明显。
3. **多模态扩展**：地图已支持，可再支持「拍照问宿舍楼」类图片问答（对接视觉模型），贴合校园真实场景。
4. **场景闭环**：除了「问」，加「办」——如报到流程清单生成、材料核对清单（可勾选）、缴费/一卡通指引卡片，让作品从问答工具升级为「新生办事助手」。

### C. 方法创新性与意图控制（20%）
1. **混合检索（强烈建议）**：当前只有向量检索。加 BM25 关键词检索（可用 rank_bm25 或 Chroma 自带），结果融合（RRF 算法），中文专名（如「馨园」「一卡通」）召回会显著变好。
2. **查询改写**：提问前先用小模型/规则把口语问题规范成检索 query（如「学费咋交」→「学费怎么交」）。
3. **Embedding 升级**：当前 MiniLM 模型中文效果一般，可换 `BAAI/bge-small-zh-v1.5` 或 `text2vec-large-chinese`，实测中文检索明显变好（需要重跑 ingest）。
4. **重排（Rerank）**：检索 top_k=8 后用 bge-reranker 精排取 top 3 进 prompt，回答质量提升一个档次。
5. **Prompt 工程文档化**：把 SYSTEM_PROMPT 的设计演进（防幻觉、来源标注、兜底话术、同义词映射）写成「意图控制策略」章节，这就是技术文档的核心卖点。
6. **多 Agent 尝试**：可引入「意图识别 Agent（路由：问答/办事/闲聊）」，体现多智能体编排能力，符合赛题「多 Agent 协同」方向。

### D. 用户体验与产品精细度（15%）
1. **对话持久化**：现在刷新页面聊天记录就没了，改用 `st.session_state` + 本地存储或后端 SQLite 存历史。
2. **思考可视化**：已有「正在思考…」与检索过程，可改成更精致的「检索 → 生成」分步状态条。

5. **回答复制/分享按钮、字号调节、深色模式**：锦上添花，成本低。
6. **加载动画与骨架屏**：地图加载时给出占位，避免白屏。

## 七、常见问题速查（踩坑提醒）

- **启动报 ModuleNotFoundError**：确认用的是 `D:\新生指南\.venv\Scripts\python.exe`，不要用系统 Python。
- **embedding 模型下载失败**：`chroma_store.py` 已设置 `HF_ENDPOINT=https://hf-mirror.com`，若仍失败，检查网络，或手动下载模型放到 HuggingFace 缓存目录。
- **中文乱码**：前端已用增量 UTF-8 解码，若你自己写脚本处理文本，务必用 `encoding="utf-8"`。
- **改完知识库没生效**：必须重跑 `scripts/ingest.py` 并**重启后端**（向量库在服务启动时加载，改库后要重启）。
- **地图显示失败**：确认文件在 `D:\新生指南\校园地图.png`，路径与 `app.py` 中一致。
- **流式回答中途断**：多为 DeepSeek 限流/网络抖动，代码已兜底，多试一次或检查 key 余额。
